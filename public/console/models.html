Why Random Forest Over Deep Neural Networks?

Deep Learning (Transformers, LSTMs) introduces 15–40ms latency overhead, violating real-time DNS SLAs. 150-tree Random Forest achieves 1.1ms latency with exact TreeSHAP game-theoretic explainability.

Why Unicode TR39 & Jaro-Winkler for Homoglyphs?

Standard edit distance (Levenshtein) fails to detect visual spoofing (e.g. Cyrillic `о` in `gооgle.com`). Unicode TR39 skeletons normalize visual confusables before string distance comparison against top 10,000 corporate domains.

  • check_circle Unicode TR39 confusable transformation mapping
  • check_circle Jaro-Winkler prefix-weighted accuracy (>0.88 threshold)
  • check_circle Near-zero false positive rate on internationalized TLDs
timeline

Why Sequential Markov Chains for DNS Tunnelling?

Data exfiltration tools (Iodine, DNScat2) disguise base64/hex bytes as subdomains. 1st-order Markov transition matrices detect anomalous character sequences in sliding windows without payload decryption.

  • check_circle Covert payload detection in TXT/A/CNAME records
  • check_circle Defeats high-entropy exfiltration channels
  • check_circle Character bigram transition anomaly scoring

Why Redis Murmur3 Bloom Filter as Stage 1?

Top 100k verified enterprise services (M365, AWS, Google) account for 90%+ of corporate traffic. A 1.2MB Murmur3 bitset bypasses benign queries in sub-0.1ms with mathematically guaranteed zero false negatives.

  • check_circle <0.1ms in-memory cache lookup time
  • check_circle Murmur3 5-hash bit matrix (1.2 MB RAM)
  • check_circle Eliminates 90% of ML inference load
